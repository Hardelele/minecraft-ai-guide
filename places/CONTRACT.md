## Вход

Куб 32×32×32 мировых блоков. Начало куба — мировая клетка `(x0, y0, z0)`; клетка `(x, y, z)` мира
лежит в индексе `[x-x0][y-y0][z-z0]`. На каждую клетку one-hot из `C_IN = 16` каналов
(ровно одна единица, остальные нули), порядок каналов:

| # | канал | что сюда попадает |
|---|---|---|
| 0 | air | воздух; также неполные непроходимые-не-мешающие блоки без коллизии: снег-слой, ковёр, рельсы, редстоун, кнопки, рычаги, таблички, нажимные плиты, паутина |
| 1 | unseen | агент клетку не видел / нет данных (незагруженный чанк) |
| 2 | water | вода (текущая и стоячая) |
| 3 | lava | лава; огонь |
| 4 | ground | dirt, grass, sand, gravel, clay, mycelium, podzol, farmland, soul sand, snow block, ice, netherrack, end stone (метки Semantics `ground`) |
| 5 | stone | природный камень: stone, granite/diorite-подобные модовые, sandstone, hardened/stained clay в мезе, obsidian, bedrock (метка `stone`, кроме cobblestone и mossy cobble — они built_solid) |
| 6 | ore | руды (метка `ore`) |
| 7 | wood_natural | брёвна и листва (метки `wood`, `leaves`) |
| 8 | plant | трава, цветы, саженцы, кусты, кактус, тростник, грибы, тыквы/арбузы, лианы НЕ сюда (см. 12), пшеница и прочие посадки (метка `plant`) |
| 9 | built_solid | то, что ставят игроки: доски, булыжник, mossy cobble, кирпичи, каменный кирпич, стекло и панели, шерсть, плиты, ступени, кварц, блоки металлов, светокамень, лампы, кровать, книжные полки, модовые `building`/`decor`/`pipe`/`machine` без хранилища, если они твёрдые — см. 14 |
| 10 | door | двери (дерево/железо), люки, калитки забора |
| 11 | fence | заборы, стены из булыжника (cobble wall), железные решётки, nether fence |
| 12 | climb | лестницы (ladder) и лианы (vine) |
| 13 | light | факелы, redstone-факелы, фонари без коллизии (метка-исключение: всё с излучением света и без полного куба) |
| 14 | storage | сундуки, печи, верстак, наковальня, зачаровальный стол, варочная стойка, раздатчики, воронки, модовые `storage`/`machine` (блоки с tile entity) |
| 15 | other_solid | всё остальное твёрдое, неизвестное (модовые блоки, которые правила не узнали) |

Клетки куба с `y < 0` — other_solid, с `y > 255` — air.

Порядок важен только как номер канала. Правила отнесения блоков в Python — `places/channels.py`
(по числовым id 1.7.10 и именам из реестра FML в `level.dat`); Java может опираться на `Semantics`
и `Material`, точное совпадение в спорных блоках не требуется — модель учится с шумом.

## Выход

На каждую клетку `K = 8` логитов (класс — argmax):

| # | класс | смысл |
|---|---|---|
| 0 | solid | твёрдое/неважно (сплошной природный массив, земля, вода/лава, листва и т.п.) |
| 1 | open_outside | открытый воздух под небом |
| 2 | passage | коридор/тоннель/проход шириной ≤ 3 |
| 3 | room | замкнутый воздух внутри постройки |
| 4 | cave_hall | большой природный подземный объём |
| 5 | shaft | вертикальный ствол/колодец/лестничный пролёт |
| 6 | junction | развилка проходов |
| 7 | built_structure | твёрдые клетки постройки: стены, пол, крыша, двери |

## Архитектура (фиксирована)

3D U-Net глубины 2, тензоры NCDHW, `N=1, C, D=x, H=y, W=z`.

- `Block(cin, cout)` = `Conv3d(cin→cout, k=3, stride=1, pad=1, нулевой паддинг)` → ReLU → `Conv3d(cout→cout, k=3, pad=1)` → ReLU.
- `e1 = enc1(x)` : 16→16, 32³
- `e2 = enc2(maxpool2(e1))` : 16→32, 16³
- `b = bott(maxpool2(e2))` : 32→64, 8³ — **bottleneck** (после второго ReLU)
- `d2 = dec2(cat[up2(b), e2])` : 96→32, 16³
- `d1 = dec1(cat[up2(d2), e1])` : 48→16, 32³
- `logits = head(d1)` : Conv3d k=1, 16→8, без активации.

`maxpool2` — MaxPool3d(kernel 2, stride 2). `up2` — nearest ×2: `out[i][j][k] = in[i/2][j/2][k/2]`
(целочисленное деление). `cat` — по каналам, порядок `[upsampled, skip]`: каналы 0..63 — up2(b),
64..95 — e2. BatchNorm нет (сеть учится без нормализации; если появится — будет слита в conv до экспорта).

Свёртка: `out[o][x][y][z] = b[o] + Σ_i Σ_{dx,dy,dz∈0..2} w[o][i][dx][dy][dz] · in[i][x+dx-1][y+dy-1][z+dz-1]`
(кросс-корреляция, как в PyTorch; за краем — 0).

## Эмбеддинг места

Место — множество клеток куба (связная область одного класса). Эмбеддинг = среднее по клеткам
места векторов bottleneck `b[:, x/4, y/4, z/4]` (64-d, nearest-upsample ×4 до клеток), затем
L2-нормировка.

## Формат `places.bin` (little-endian)

```
"PLC1"            4 байта ASCII
int32 version = 1
int32 C_IN = 16
int32 K = 8
int32 n_tensors = 22
n_tensors раз:
  int32 len, UTF-8 name[len]
  int32 ndim, int32 shape[ndim]
  float32 data[prod(shape)]   row-major (как PyTorch .contiguous())
```

Тензоры в этом порядке: `enc1.c1.w, enc1.c1.b, enc1.c2.w, enc1.c2.b, enc2.c1.w, enc2.c1.b, enc2.c2.w,
enc2.c2.b, bott.c1.w, bott.c1.b, bott.c2.w, bott.c2.b, dec2.c1.w, dec2.c1.b, dec2.c2.w, dec2.c2.b,
dec1.c1.w, dec1.c1.b, dec1.c2.w, dec1.c2.b, head.w, head.b`. Формы весов conv —
`[cout, cin, 3, 3, 3]` (head — `[8, 16, 1, 1, 1]`), смещений — `[cout]`. Всего 359 880 чисел,
файл 1 440 172 байта.

## Формат `places-test.bin`

Тот же контейнер с другим заголовком:

```
"PLT1"
int32 version = 1
int32 n_tensors = 3
  "input"      [1, 16, 32, 32, 32]  one-hot (float32 0/1)
  "logits"     [1, 8, 32, 32, 32]   ожидаемый выход head
  "bottleneck" [1, 64, 8, 8, 8]     ожидаемый b
```

Java-вывод с весами из `places.bin` на `input` должен дать `logits` и `bottleneck` с
максимальной абсолютной ошибкой ≤ 1e-4. Тестовый файл всегда соответствует весам, лежащим
рядом в том же коммите.

Python-читатель/писатель обоих файлов — `places/export.py` (`read_tensors`, `write_tensors`).
