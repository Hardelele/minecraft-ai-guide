# places — модель распознавания мест

Лёгкая 3D-сеть (U-Net глубины 2, 360 тыс. весов, 1,4 МБ) размечает куб 32×32×32 блоков по
классам мест: открытое небо, проход, комната, пещерный зал, ствол, развилка, стены постройки.
Bottleneck даёт 64-мерный эмбеддинг места для поиска. Контракт с Java-выводом —
[`CONTRACT.md`](CONTRACT.md); веса — `res/assets/aiguide/places/places.bin`, сверка — `places/places-test.bin`.

## Файлы

| файл | что делает |
|---|---|
| `names.py` | имена каналов и классов (без torch — его импортируют рабочие процессы) |
| `model.py` | сеть, порядок тензоров для экспорта |
| `world.py` | чтение копий миров Anvil 1.7.10 (свой мини-NBT), реестр FML из `level.dat` |
| `channels.py` | блок → входной канал по имени из реестра (ваниль — таблицей, моды — шаблонами имён) |
| `label.py` | слабая разметка правилами по полной геометрии |
| `vis.py` | маска видимости: лучи радиусом 20 из точек, где можно стоять |
| `extract.py` | кубы из миров → `build/places/real/<мир>.npz` |
| `synth.py` | синтетические сцены с известной разметкой → `build/places/synth/*.npz` |
| `train.py` | обучение и оценка (IoU, матрицы ошибок) → `build/places/ckpt/` |
| `export.py` | `places.bin`, `places-test.bin`, скорость на CPU |
| `viz.py` | PNG-срезы: вход / разметка / предсказание |

## Пересобрать данные и переобучить

Все команды — из корня ворктри; большие данные — в `build/places/` (не в git).

```
# 1. копии миров (только копировать! боевой сервер не трогать, занятые файлы пропускать):
#    build/places/worlds/<имя>/level.dat и build/places/worlds/<имя>/region/*.mca
# 2. кубы из миров (≈10 мин на 8 ядрах)
python places/extract.py --procs 5
# 3. синтетика (≈10 мин)
python places/synth.py --n 6000 --seed 0 --out build/places/synth/train.npz
python places/synth.py --n 600  --seed 1 --out build/places/synth/val.npz
python places/synth.py --n 300 --kind houses_unusual --seed 2 --out build/places/synth/ood-houses_unusual.npz
python places/synth.py --n 300 --kind tunnels_bare   --seed 3 --out build/places/synth/ood-tunnels_bare.npz
python places/synth.py --n 300 --kind decor          --seed 4 --out build/places/synth/ood-decor.npz
# 4. обучение (GPU) и оценка
python places/train.py --minutes 40
# 5. экспорт и скорость
python places/export.py --ckpt build/places/ckpt/best.pt --speed
# срезы для глаз
python places/viz.py build/places/real/server.npz --n 12
```

Миры для проверки (`VAL_WORLDS` в `train.py`) в обучение не попадают. Копии одной карты с
прогонов агентов (`nb-*`, один seed) берутся только две, чтобы не перевешивали.

## Правила слабой разметки (`label.py`)

Пространство — клетки air/plant/climb/light. На окне куба с запасом 12 клеток:

- **небо**: над клеткой нет блокирующих блоков до верха мира (листва, заборы, факелы не блокируют) → `open_outside`;
  укрытые клетки в двух шагах от неба (навесы, под деревом) — тоже `open_outside`, если это не комната;
- **ствол**: пробег воздуха по X и по Z ≤ 3, по Y ≥ 5, со всех четырёх сторон в пределах 12 — не листва → `shaft`;
- **комната**: укрыто, луч вверх упирается в постройку (built_solid/door/fence/storage), из четырёх горизонтальных
  лучей ≥ 3 упираются в постройку → `room`; длинное узкое (ширина ≤ 3, длина ≥ 6) внутри постройки — `passage`;
- **ширина**: минимум пробегов по X, Z и диагоналям (×√2), затем максимум по окрестности 5×3×5 —
  чтобы рваные края зала не становились проходом; ширина ≤ 3,5 → `passage`;
- широкое укрытое природное: связная область ≥ 120 клеток → `cave_hall`, меньше → `passage`;
- **развилка**: клетка прохода, у которой проходная область внутри куба 7³ выходит на его оболочку ≥ 3 кусками,
  плюс соседи → `junction`;
- **постройка**: связные (26) куски built/door/fence/storage, касающиеся комнаты (в пределах 2), или большие
  стенообразные (≥ 40 клеток, высота ≥ 3, длина ≥ 4) → `built_structure`;
- карманы < 6 клеток, вода, лава, земля, камень, листва → `solid`; незагруженные чанки — игнор.

Синтетика размечается теми же правилами, а то, что генератор знает точно (интерьеры, стены домов из любых
материалов, тоннели, развилки, стволы, залы), перекрывает их.

## Результаты базовой версии (2026-11-08)

Данные: 12 копий миров (боевой сервер — 31 регион, 6 локальных сохранений, 5 миров с прогонов
на ноутбуке, из них 5 — одна карта с одним seed), 2 354 реальных куба; в обучение — 1 873 куба
из 7 миров, на проверку — миры `ii-mir` (136) и `novyi1` (164), не виденные при обучении.
Синтетика: 6 000 сцен в обучение, 600 — на проверку (другие seed), по 300 сцен в три набора
«не выучен ли случайный признак». Батч 16 = 8 реальных + 8 синтетических (76 % синтетики по
кубам в наборе), 70 % примеров с маской видимости. 35 минут на RTX 5060 Ti, 37 374 шага,
AdamW 2e-3 с косинусом, bf16, взвешенная cross-entropy, повороты вокруг Y и отражение.

IoU лучшего чекпойнта (без маски / с маской видимости; с маской счёт только по виденным клеткам):

| набор | mIoU | solid | open | passage | room | cave_hall | shaft | junction | built_str |
|---|---|---|---|---|---|---|---|---|---|
| миры проверки | 0,71 | 1,00 | 0,99 | 0,65 | 0,74 | 0,88 | 0,42 | 0,37 | 0,63 |
| миры проверки, маска | 0,66 | 0,99 | 0,99 | 0,61 | 0,64 | 0,85 | 0,36 | 0,33 | 0,48 |
| синтетика проверки | 0,84 | 1,00 | 1,00 | 0,88 | 0,97 | 0,97 | 0,67 | 0,34 | 0,89 |
| синтетика, маска | 0,79 | 0,99 | 1,00 | 0,83 | 0,89 | 0,97 | 0,42 | 0,37 | 0,84 |

В реальных мирах проверки комнат почти нет (3 253 клетки), поэтому room там
мерится на малом числе. Метки реальных миров — правила, т. е. IoU меряет согласие с правилами.

Проверка случайных признаков (`build/places/ckpt/eval.json`, матрицы ошибок там же):

- **дома из брёвен / неизвестных модовых блоков / руды** (в обучении дома только из built_solid,
  камня и земли): комнаты узнаются на 67 % клеток (29 % уходят в open_outside), стены — на 55 %
  (45 % — в solid). Модель **частично опирается на материал**: дом из «природных» блоков для неё
  похож на скалу. Лечится домами из любых материалов в синтетике.
- **тоннели без факелов и крепи** (рельсы и так — канал air): passage 0,94 IoU, recall 97 % —
  тоннель узнаётся по форме, не по факелам.
- **декор** (колонны, стены, арки, заборы, кучи блоков): ложных комнат 94 клетки на 5,7 млн
  открытого воздуха; но 6 351 клетка куч и колонн (по правилам — solid) названа built_structure:
  модель зовёт постройкой любой поставленный игроком блок.

Скорость на CPU (PyTorch, один куб, машина под нагрузкой: Minecraft и OBS): 1 поток —
280–320 мс, 4 потока — 132 мс. Оценка счёта: ≈ 2 млрд умножений-сложений на куб.

## Что модель умеет и чего не умеет

Умеет: небо/землю; природные тоннели и залы; шахтёрские тоннели любой ширины 1–3 с лестницами;
комнаты в домах из привычных материалов; стволы с лестницей и колодцы (shaft 0,67 на синтетике);
работать по частично виденному кубу.

Не умеет / слабо:
- **развилки** (junction 0,34–0,37): чаще путает с проходом; правило для реальных пещер само
  шумное (ложные развилки на изгибах).
- **стволы в реальных мирах** (0,42): правило ловит и щели между блоками.
- дома из брёвен, модовых и «природных» блоков (см. выше);
- кучи блоков и колонны называет built_structure;
- в невиденных клетках выдаёт что попало (их нет в ошибке при обучении) — брать только виденные;
- длинные коридоры внутри построек правила зовут passage, короткие — room (граница 6 клеток);
- реальных построек игроков в данных мало (на срезах видны данжи и заброшенные шахты),
  так что room/built_structure держатся на синтетике.
