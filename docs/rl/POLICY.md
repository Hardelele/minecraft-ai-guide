# Политика экипажа: своя сеть вместо DeepSeek (ветка `rl/policy`)

Мозг агентов — маленькая сеть, обученная с подкреплением (PPO) на действиях и наблюдениях среды
(`docs/rl/CONTRACT.md`, ветка `rl/env`). Без учителя-правил: с первого шага агент сам выбирает из 38 действий,
`noop` доступен всегда и стоит −1 с перезапуском мира. DeepSeek — только флагом `-Daiguide.mind=llm`.

## Как устроено

| что | где |
|---|---|
| пространства (действия, признаки, веса награды) | `rl/*.json` из `RlSpec.java` (среда); Python читает их в `tools/rl/spec.py` |
| маска в Python | `tools/rl/spec.py: allowed` — построчный перенос `RlSpec.allowed`; сверяется с Java тестом |
| симулятор | `tools/rl/sim_env.py` — грубая модель мира той же формы (сырые факты под именами `RlEnv.facts`) |
| сеть | `tools/rl/policy.py`: 137 → 256 → 256 → 38 (tanh), бегущая нормировка входа, маска на логитах; критик той же формы |
| обучение | `tools/rl/train.py`: PPO с маской, учебная программа, нормировка награды, снимки по эпохам |
| реальная среда | `tools/rl/real_env.py` поверх `tools/rl/env_client.py` (ветка среды), `train.py --env real --url host:port,...` |
| экспорт | `tools/rl/export_policy.py` → `res/assets/aiguide/rl/policy.bin` + `rl/policy-test.bin` |
| вывод в игре | `PolicyNet.java` (чистая Java 8), `PolicyMind.java` (решение мозга), `RlEnv.facts` (общий код фактов) |
| кривые | `tools/rl/curves.py` → `build/rl/runs/<run>/curves*.png`, `curves.csv` |
| проверка на симуляторе | `tools/rl/play.py` (успех, время, что выбирает; `--trace` — эпизод по шагам) |

Наблюдение и маска в игре строятся **тем же кодом, что в среде**: `RlEnv.facts` разделён на экземплярный (эпизод
среды) и статический `facts(crew, agent, world, scenario, memo, time, progress)`, который зовёт и `PolicyMind`.
Цель мозга переводится в ближайший сценарий (`PolicyMind.scenario`: предмет цели, слова, «защищай базу» + волны).

## Сеть

MLP с общими весами для всех агентов (номер агента и размер экипажа — во входе). Почему не трансформер по агентам:
агенты решают по одному в своих точках решения, а про других вход уже несёт сводку (союзники, пост, стена);
MLP в Java — три умножения матрицы на вектор. Параметры: актор 137·256+256 + 256·256+256 + 256·38+38 = 110 886,
критик 101 377 (в Java не нужен); вместе ≈ 212 тыс. В `policy.bin` — актор и нормировка входа (444 811 байт).

## PPO (по умолчанию)

γ 0.99, λ 0.95, клип 0.2, 4 прохода, мини-пачка 1024 из 8192 решений, Adam 3e-4, норма градиента 0.5,
коэффициент ценности 0.5, энтропия 0.05 → 0.01 линейно за сессию. Награда делится на бегущее СКО
дисконтированного возврата (как `NormalizeReward`), преимущества нормируются в пачке. Переходы — по потокам
«среда × агент»: награда шага — то, что агент накопил до своего следующего решения; GAE по потоку, обрезка с
оценкой ценности в конце пачки. Эпоха = одна итерация PPO.

## Против «утонуть в минусах»

- **маска**: недопустимое не выбирается никогда (логит −1e8), но `noop` доступен — его цена учится сама;
- **нормировка награды** по СКО возврата и преимуществ в пачке;
- **учебная программа**: `wood → pickaxe → sword → iron → food → fortify → waves:easy → waves:normal`;
  переход при успехе ≥ 0.8 за последние 200 эпизодов этапа; 30 % эпизодов — прошлые этапы (не забывать),
  15 % — следующий («подсмотреть»); для волн «успех» на стороне политики — отбить ≥ 5 волн (у среды цели нет);
- **подсказочный бонус (shaping)**, флаг `--shaping` (по умолчанию 0): потенциальный `γΦ(s') − Φ(s)`,
  Φ = прогресс цели сценария + шаги цепочки крафта (дерево → верстак → деревянная кирка → булыжник; для железа —
  руда, печь, слитки). Потенциальный бонус не меняет, какая политика лучшая. Есть только в симуляторе.

## Запуск

```
python tools/rl/train.py --run sim1 --minutes 25 --shaping 1.0          # симулятор, GPU; 3 процесса симулятора, BelowNormal
python tools/rl/play.py --weights build/rl/runs/sim1/final.bin           # успех по сценариям
python tools/rl/curves.py --run sim1 [--dark]                            # кривые
python tools/rl/export_policy.py --ckpt build/rl/runs/sim1/final.pt      # в мод: policy.bin + policy-test.bin
python tools/rl/train.py --env real --url 127.0.0.1:26100,127.0.0.1:26101 --init build/rl/runs/sim1/final.pt --run real1
```

CPU: torch на 2 потоках, симулятор в 3 процессах, всё с приоритетом BelowNormal; обучение — на GPU.

## Веса в ветке (для мода и для съёмки)

| файл | что это |
|---|---|
| `res/assets/aiguide/rl/policy.bin` | «сеть после симулятора»: идёт в jar клиента (`tools/build_client.py`), мозг по умолчанию |
| `rl/policy-test.bin` | сверка Java с PyTorch для этих весов (`PolicyTest`) |
| `rl/snapshots/policy-epoch-0.bin` | необученная сеть (та же инициализация, что у обучения: `torch.manual_seed(1)`) |
| `rl/snapshots/policy-epoch-1.bin`, `-10`, `-50` | после 1, 10, 50 эпох обучения на симуляторе (прогон `sim1`) |

Подставить в мод (клиентский jar с этой ветки; JVM-флаги сервера/одиночной игры):

```
-Daiguide.mind=policy                                                # (по умолчанию) мозг — политика
-Daiguide.policy.weights=<путь>\rl\snapshots\policy-epoch-0.bin      # другой снимок вместо policy.bin из jar
-Daiguide.policy.sample=true                                         # выбирать по вероятностям, как при обучении
```

Для «до/после» честнее `sample=true` у всех снимков: необученная сеть тогда выбирает почти случайно (как в
начале обучения), а не одно и то же действие. Без флага — лучшее действие (для показа обученной сети).

## В игре

По умолчанию мозг — политика (`-Daiguide.mind=policy`); модель — `-Daiguide.mind=llm`. Веса — из jar
(`/assets/aiguide/rl/policy.bin`) или `-Daiguide.policy.weights=<файл>`; `-Daiguide.policy.sample=true` — выбор по
вероятностям, а не лучший. В игре `noop` замаскирован (мир не перезапускается); цель с предметом закрывается
сама, когда предмет есть. Без весов цель кончается «no policy: …» (на DeepSeek молча не переходит).
Каждое решение — строка `mind: Agent N policy -> <действие> (p …, scenario …, … ms)` в событиях.
