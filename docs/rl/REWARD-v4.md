# Награда v4: исходы и общий причинный кредит

Файлы: `rl/reward-v4.json` (параметры), `rl/events.json` (формат событий), `tools/rl/reward_core.py` (эталон),
`client/src/hardelele/aiguide/client/RlReward4.java` (зеркало, проверяется на тех же случаях), тесты лазеек —
`tools/tests/test_rl_exploits.py`.

## Зачем

В v3.1 награда — около 50 ручных весов (`time`, `stall`, `skill_ok/fail`, `retry_fail`, `switch_ok`,
`perimeter.kill`, `clean_wave`, `wave_cleared`, `holes_at_wave`, `out_died`, `hurt_inside`…), и каждая лазейка
сети латается ещё одним весом. В v4:

1. **Платятся только исходы**: база цела (прорывы, мобо-секунды внутри), экипаж жив (смерти, урон), шкалы
   развития растут (веса шкал — прежние, из `rl/reward.json`), цель сценария, ручная оценка, `noop`. Плюс один
   общий штраф `afk` за время без прогресса — растёт с длительностью простоя, с потолком.
2. **Всё прочее — общий причинный кредит**: каждая угроза (моб с целью) — «пирог» ценой той потери, которую она
   причинила бы; когда угроза снята (убита, ушла), пирог делится между решениями, которые изменили её ход
   (блок изменил путь, атака не прошла, удар). Без правил под приёмы: любой новый приём, который снимает угрозы,
   получает кредит через те же события.
3. **Кредит за моба/блок — только если агент это видел** (сам, лучом Sight в пределах дальности, или стоя в
   `sight.near_r` от видевшего).

## Поток событий

Среда (Java `RlEnv`, Python-симулятор, пакетный симулятор) на каждом шаге выдаёт кадры
`{t, dt, phase, events:[…]}` (`rl/events.json`): `t` — игровые секунды на конец кадра, `dt` — его длина,
`phase` ∈ `day|night|prep|wave|break`. События обрабатываются по порядку списка.

| событие | поля | кто выдаёт |
|---|---|---|
| `agent` | agent, x, y, z, hp, alive, base_dist | состояние каждого агента, хотя бы раз в кадр (первым) |
| `decision` | agent, id, kind | агент начал решение (id — `decision_id`, kind — id действия) |
| `noop` | agent | агент выбрал `noop` (эпизод кончается) |
| `goal` | — | цель сценария достигнута |
| `human` | agent, rating | ручная оценка |
| `damage` | agent, hp, mob?, cause? | агент получил урон (mob — от какого моба) |
| `death` | agent, cause, base_dist | агент погиб; cause ∈ `death.accident_causes` — несчастный случай |
| `breach` | mob | враг впервые за волну внутри периметра |
| `inside` | mob_s | мобо-секунды внутри периметра за кадр |
| `scale` | agent \| `"*"`, key, delta, causes?, res? | изменение измеренной части шкалы (`safety.wall`, `mine.iron`, …); `"*"` — экипажу (каждому живому); causes — решения, менявшие измеряемое; res — найденный ресурс, из которого прирост |
| `found` | agent, decision, res, key, amount | агент нашёл ресурс/путь `res` (впервые в эпизоде); key/amount — какую шкалу и насколько он может дать |
| `threat` | mob, kind, target, dmg, stay_s? | моб взял цель: `"base"` или агента; dmg — урон его удара; stay_s — сколько он пробыл бы внутри, попав на базу (остаток его волны). Мобы волны — угрозы базе с появления |
| `fall` | why | база сдана (`noop`) или потеряна (`lost`): все открытые угрозы состоялись. Перед ним среда выдаёт `threat` для ещё не пришедших мобов сценария (остаток волны, волны до конца эпизода) |
| `path_changed` | mob, effect, delay_s, on_route, by, seen | путь моба изменён блоком/рвом/ямой: `detour` (обошёл, задержка delay_s), `stuck`, `fell`, `blocked`; on_route — изменённый участок лежит на его пути к цели; by — решения, поставившие/выкопавшие эти блоки; seen — агенты, видевшие это |
| `attack_failed` | mob, target, reason, by?, seen | атака по агенту не прошла: `moved` (сместился), `cover` (блок между ними: стрела в блок, зомби не дотянулся), `reach`; by — решения, поставившие закрывший блок (для `moved` — пусто: берутся решения цели за `threat.dodge_s`) |
| `kill` | mob, agent, decision, seen? | агент убил моба (decision — удар) |
| `mob_gone` | mob, why | моб ушёл без исхода: исчез, волна кончилась |
| `novel` | agent, decision? | новая в эпизоде связь «причина × следствие» на мобе/животном/спасении (бывший `curiosity.novel`) |

`seen` — список агентов, которые видели событие сами (Sight: луч от глаз без твёрдых блоков, дальность ≤ 16 /
поле зрения как у `Sight`). Ядро добавляет «стоял рядом»: агент засчитан, если он в `seen` или в `near_r` от
кого-то из `seen` (по последним `agent`-событиям).

## Что ядро считает

Состояние эпизода: последние `agent`; решения (id → агент, начало, фаза, «продуктивное»); открытые угрозы
(mob → цели, урон удара, вклад решений, урон, уже нанесённый каждой цели); находки (res → решение, агент,
ценность); решения последнего «светлого» периода (`calm_phases`: day/prep/break).

Награда агента копится в компонентах и забирается средой на его следующем решении (как `RlReward.take`).
Кредит к прошлому решению — ещё и **событие переноса** `{"type":"reward","agent","key","points","move",
"chain":[{"decision_id",…,"via":"credit"}]}` в `info.events`: `train.py` переносит `move × points` с шага, где
очки получены, на переход того решения (`credit.redistribute`, `move` вместо общего beta).

### Исходы

| компонент | сумма |
|---|---|
| `noop` | `outcomes.noop` (−1) |
| `surrender` | на `fall`: каждая открытая угроза базе — прорыв (если моб ещё снаружи) и мобо-секунды его пребывания до конца волны, каждому живому; угроза агенту — её ценность (ниже). Сдаться в проигрываемой волне = отдать всё, что ещё придёт, поэтому дороже, чем биться |
| `goal` | `outcomes.goal` каждому агенту |
| `human` | `outcomes.human × rating` |
| `crew.damage` | `outcomes.crew.damage × hp` |
| `crew.death` | `−|death| × (accident_x если несчастный случай) × (1 + min(far_cap, max(0, base_dist − base_r) × far_per_block)) + min(soften_cap × |death|, finds_soften × ценность находок вылазки)`; вылазка — с последнего пребывания агента в `base_r` от базы |
| `base.breach` | `outcomes.base.breach` каждому живому агенту |
| `base.mob_seconds` | `outcomes.base.mob_seconds × mob_s` каждому живому |
| шкалы (`safety.wall`, …) | `вес(rl/reward.json) × delta × множитель сценария`; агенту или каждому живому (`"*"`) |
| `curiosity.novel` | вес шкалы × множитель, **кроме фаз `no_curiosity_phases`** (волна, ночь) |
| `afk` | за кадр: `F(idle + dt) − F(idle)`, `F(x) = rate·((x−g)²/2r` при g ≤ x < g+r; `rate·(r/2 + x−g−r)` при x ≥ g+r; 0 до g), g = `grace_s`, r = `ramp_s`: штраф в секунду растёт от 0 до `rate` за r секунд после g секунд простоя. Не зависит от длины кадра |

**Прогресс** (сбрасывает простой `idle` в 0): положительная выплата шкалы, `goal`, положительный `human`, новая
находка, кредит угрозы решению агента, начатому не раньше `afk.active_s` назад. Кредит старому решению (коробка,
построенная давно) простой **не** сбрасывает: сидеть в коробке — АФК.

### Угрозы: общий кредит за снятую угрозу

Угроза открывается событием `threat` (повторный `threat` того же моба добавляет цель). Ценность угрозы
`V = max` по её целям: база — `|base.breach|` (если моб ещё снаружи) `+ |base.mob_seconds| × оставшееся пребывание`
(`stay_s` с момента `threat`); агент a — `max(0, agent_hits × dmg × |crew.damage| − урон, уже
нанесённый этим мобом агенту a × |crew.damage|)` («размен»: убил, потеряв мало HP — пирог больше).

Вклад решений (каждое решение входит в угрозу один раз — берётся наибольший вес, повторы не копятся):

| событие | условие | вес | причина (компонент) |
|---|---|---|---|
| `path_changed` | угроза открыта, `on_route`, решение видел | `w[effect]`, для `detour` × `delay_s / (delay_s + delay_tau_s)`; делится поровну на `by` | `credit.block` |
| `attack_failed` `cover`/`reach` | угроза открыта, видел | `w.cover` / поровну на `by` | `credit.cover` |
| `attack_failed` `moved` | угроза открыта, цель видела моба | `w.moved` / поровну на решения цели за `dodge_s` | `credit.dodge` |
| `kill` | — | `w.kill` | `credit.kill` |

Исход угрозы (один раз):

- `kill` → пирог `threat.kill × V` делится по весам вкладов;
- `mob_gone` → пирог `threat.deter × V` (отпугнул/задержал, но не убил — половина);
- `breach` (угроза базе дошла) → прорыв заплачен, вклады до него обнулены (не удержали); угроза остаётся —
  теперь это её пребывание внутри, убийство внутри снимает оставшиеся мобо-секунды;
- `fall` → угроза считается состоявшейся (сдача/поражение).

Пирог по одной угрозе не больше потери, которую она причинила бы, поэтому **сумма кредитов не может превысить
удержание базы**: убить моба у стены = ровно один предотвращённый прорыв, стенка в никуда (`on_route = false`)
ничего не получает, бесконечные уклонения от одного моба дают его пирог один раз.

### Выжил на грани (`credit.survive`)

HP агента упало до `survive.hp_low` при открытой угрозе ему → начало опасности; если затем HP поднялось до
`hp_safe` без смерти — `share × |crew.death|` делится поровну на решения агента с начала опасности (отступил,
поел, вылечился). `share` (0.1) меньше урона, которым платишь за спуск до `hp_low` (14 HP × 0.01 = 0.14), — нарочно
подставляться невыгодно.

### Переносы (сумма экипажа не меняется)

- **Разведка** (`credit.scout`): прирост шкалы с `res`, найденным агентом A (`found`), — `scout.share` очков
  получателя переносится A (на его решение-находку). Ценность находок вылазки смягчает её смерть, а сам перенос
  от смерти не зависит: **разведка не пропадает**.
- **Пустой день** (`credit.wasted_day`): потеря в фазе не из `calm_phases` (смерть, прорыв, мобо-секунды) — её
  доля `wasted_day.share` переносится на непродуктивные решения последнего светлого периода всего экипажа
  (поровну по длительности). Продуктивное решение — получившее положительную выплату/кредит или находку.
- **Причины шкалы** (`credit.scale`): `scale_move` от выплаты шкалы с `causes` переносится на эти решения
  (бывший `--credit` для шкал).

### Кадр по шагам

1. Если фаза светлая, а прошлая — нет: новый светлый период (список дневных решений очищается).
2. События по порядку (таблица выше).
3. После событий: опасность/выжил (`survive`); `afk` каждому живому за `dt`.

## Python-симулятор

`SimEnv(reward="v4")` (или `AIGUIDE_REWARD=v4`, `train.py --reward v4`) выдаёт эти события из своего грубого мира:
решения, состояние агентов (`x = base_dist = a.dist`), урон/смерть, прорывы и мобо-секунды с id мобов волны,
угрозы базе с появления волны (`stay_s` 240), стена (≥ половины кольца) — `path_changed` (`blocked`/`detour`) на
строивших при исходе моба снаружи, видят агенты у базы; ночной сценарий — мобы агента, укрытие — `attack_failed
cover` на решения, поставившие блоки вокруг; находки руды/деревьев (`found`) и их добыча (`scale` с `res`);
`fall` на `noop` и поражении. В v4 **периметр базы есть с начала волнового сценария** (как в игре: кольцо задано при
сбросе); в v3 — как было, после постройки стены. Сценарии `delay:*` остаются на своих весах.

## Решения владельца → свойства системы (проверяются `test_rl_exploits.py`)

| решение | как получается |
|---|---|
| АФК дороже, чем дольше стоишь; коробка — АФК | `afk` растёт с простоем; кредит коробки идёт старым решениям и простой не сбрасывает |
| размен | пирог угрозы агенту минус урон от этого моба; урон — исход |
| уклонение при реальной угрозе — плюс, бегство — нет | `attack_failed moved` только у открытой угрозы, моб видели; бегство без атаки событий не даёт, а простой растёт |
| укрытие — только когда сработало и видел | `attack_failed cover` — атака была и не прошла; без `seen` — ноль |
| готовность к ночи | стена/ров к волне → `path_changed blocked` → пироги строившим; пустой день платит долю ночных потерь |
| в волну любопытство не платится | `no_curiosity_phases` |
| ночью вдали можно обороняться на месте | убийства/укрытия/уклонения недавними решениями — прогресс, простой сброшен |
| разведка не пропадает при смерти | перенос `credit.scout`, смягчение смерти находками |
| всё вместе не перевешивает базу | пирог ≤ потери; сдача реализует открытые угрозы |

## Лазейки (`tools/tests/test_rl_exploits.py`)

Для каждой — стилизованный эпизод в событиях против честной стратегии (держать базу) с ожидаемым порядком
суммарной награды экипажа: коробка и ждать, бег по кругу, стенка в никуда, сдача в волне, уклонения от одного
моба без попытки убить, разведка далеко без возврата к ночи. Плюс те же стратегии скриптом в Python-симуляторе
(`SimEnv(reward="v4")`). Любое обучение на v4 должно проходить этот набор.

## Что ушло из v3.1

`time`, `stall`, `skill_fail`, `skill_ok`, `retry_fail`, `switch_ok`, `accident` (стал множителем смерти),
`perimeter.*` (все 8: прорыв и мобо-секунды стали `base.*`, остальное — кредит угроз и пустой день),
`death` → `crew.death`, `damage` → `crew.damage`. Шкалы и их множители по сценариям — прежние.
